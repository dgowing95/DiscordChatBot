3. Image generation (when diffusion.enabled=true): separate pod + service,
   called in-cluster by the bot's generate_image tool. /health returns 200
   once the model is downloaded/loaded (first boot can take a few minutes):
   kubectl get svc <release>-diffusion-service
   kubectl logs deploy/<release>-diffusion-deployment

4. Server workspaces: the bot's run_code_sandbox tool runs in one long-lived
   container per Discord server on this node. The node needs a Docker daemon
   (required): its socket is mounted into the core pod via hostPath
   (brain.workspace.dockerSocketPath, default /var/run/docker.sock), and the
   core pod will not start without it. Core pulls the image
   (brain.workspace.image) at startup if it is missing. List the containers:
   docker ps --filter label=dcb.instance={{ .Release.Name }}
